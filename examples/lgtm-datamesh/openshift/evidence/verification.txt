LIVE-APPLY LEARNINGS (what broke, how it was fixed)
============================================================
1. build-and-push.sh exited 2 after ALL images pushed: the final hint line
   started with '--mirror-infra', which printf parsed as an option.
   Fix: printf -- '...'. (Cosmetic; images were already in the registry.)

2. All pods stuck Pending with taint node.kubernetes.io/disk-pressure:NoSchedule.
   Cause: CRC's default ~32 GB VM disk hit DiskPressure (27 GB used) once the
   nine images were pushed into the integrated registry (registry storage is
   on the node disk). Fix: 'crc config set disk-size 80' + 'crc stop/start'.
   After restart the taint cleared and all 10 pods scheduled and reached 1/1.
   Restart counts of 2-3 on the DB-backed services are the expected
   crash-loop-until-Postgres/Kafka-ready convergence, not a defect.

3. SCC behaviour confirmed exactly as designed: the Python images run
   USER 1001:0, so dropping runAsUser lets restricted-v2 assign UID
   1000650000; postgres (70) and kafka (1000) run under the datamesh-infra
   ServiceAccount bound to nonroot-v2.
