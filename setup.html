Setup & prerequisites

Running the reference, start to finish.

From a bare Fedora workstation to a fully running data mesh — kernel tuning, tooling, and a single bootstrap command that brings up the entire stack: Istio, Kafka, Postgres, OpenMetadata, observability, and every domain service.

Verified configuration

Requirement Minimum Notes
OS Fedora 44, Docker Engine (docker-ce, daemon running, user in docker group) minikube node runs containerd with runc
RAM 64 GB total 24 GB allocated to minikube profile; rest is host headroom
Disk 1 TB 30 GB free minimum for image cache + PVs
CPU 16 vCPU recommended Not strictly required but the stack is heavy

Kernel tuning

inotify limits

The capstone runs many controllers; Fedora's default 128 instances is not enough. 

sudo sh -c 'printf "fs.inotify.max_user_instances = 512\nfs.inotify.max_user_watches = 524288\n" \
    > /etc/sysctl.d/99-kubernetes.conf'
sudo sysctl -p /etc/sysctl.d/99-kubernetes.conf

Container engine

The capstone runs on Docker Engine: native docker-ce on Linux, with the daemon running and your user in the docker group. Install it from docs.docker.com/engine/install, then enable it and point the CLI at it: 

sudo systemctl enable --now docker      # or: sudo systemctl start docker
sudo usermod -aG docker "$USER"         # log out and back in afterwards
docker context use default
docker info

Membership in the docker group is root-equivalent on the host.

VM-based engines

On macOS and Windows, Docker Desktop, Colima, or Rancher Desktop can provide the engine instead. They are options, not requirements. Their VM must be sized to at least 28 GB of memory; set MINIKUBE_CPUS and MINIKUBE_MEMORY to fit it, as described below.

Fitting minikube to the engine

The profile defaults to 16 CPUs, 24 GB of memory, and an 80 GB disk. Override them before creating the profile: 

export MINIKUBE_CPUS=16
export MINIKUBE_MEMORY=24g
export MINIKUBE_DISK=80g

The docker driver on Linux ignores the disk size; data lives under the engine's data root (docker info shows it), where about 100 GB free is recommended.

Required tooling

  • docker and docker compose
  • minikube >= 1.36 — verified on 1.38.1
  • kubectl
  • helm
  • istioctl — with the full Istio distribution (not just the binary; setup-kiali.sh applies samples/addons/kiali.yaml from it)

Optional, for the Red Hat (OpenShift Local) appendix only: crc, podman, and podman compose.

Installing the Istio distribution

curl -fsSL https://github.com/istio/istio/releases/download/1.29.2/istio-1.29.2-linux-amd64.tar.gz \
    | tar xz -C ~/.local/share
ln -sfn ~/.local/share/istio-1.29.2 ~/.local/share/istio-current
cp ~/.local/share/istio-current/bin/istioctl ~/.local/bin/

Bootstrap

Bring the whole system up

cd examples/lgtm-datamesh
./scripts/bootstrap-capstone.sh

Images are built with Docker Engine and loaded into the node with minikube image load; there is no registry. Bootstrap runs 10 tiers: minikube profile, Istio, CloudNativePG operator, Postgres cluster, Kafka (Strimzi), KEDA + HTTP add-on, OpenMetadata + observability, all services + scalers + seed data, Kiali, and catalog ingestion + lineage.

Restore baseline after running demos

./scripts/restore-baseline.sh

The demo scripts clean up their own releases on success. After running several, shared services may be missing. restore-baseline.sh puts the workloads back in their bootstrap state.

Verifying the stack

Cluster status

./scripts/cluster-status.sh

Quick verification demos

  1. ./demos/demo-order.sh — creates an order via REST, confirms it in Postgres
  2. ./demos/demo-service.sh inventory — builds, deploys, and health-checks a service
  3. ./demos/demo-observability.sh — verifies Prometheus is scraping and Grafana is provisioned

Accessing the tools

The tools run inside the cluster and are exposed as NodePort services published on 127.0.0.1 when the capstone minikube profile is created. Nothing runs in the background and nothing needs starting per demo. Ports are fixed at creation; an older profile without them is refused by setup-capstone-profile.sh and recreated with ./scripts/setup-capstone-profile.sh --replace. --replace deletes and recreates the cluster, so run ./scripts/bootstrap-capstone.sh again afterwards. Run the workshop in isolation: shut down CRC, other minikube profiles, and other workloads first so the host ports are free. To see which endpoints are published and reachable: 

./scripts/show-endpoints.sh

(Prometheus uses host port 9091 because Fedora ships Cockpit on 9090.)
